# مدار المبيعات — إدارة المبيعات والعملاء والمديونيات

تطبيق ويب عربي RTL لإدارة العملاء والفواتير والتحصيلات والمديونيات والعمولات، مع تخزين محلي في المتصفح وتهيئة أولية للربط بـ Supabase.

## المتطلبات
- Node.js 20 أو أحدث (يفضل LTS).
- npm.
- متصفح حديث.
- اتصال بالإنترنت مطلوب فقط لتحميل مكتبة Excel عند استيراد `.xlsx` والخط العربي، ويمكن استيراد CSV دون المكتبة.

## التشغيل محليًا
1. فك ضغط المشروع.
2. افتح الطرفية داخل مجلد المشروع.
3. نفّذ:
   ```bash
   npm install
   npm run dev
   ```
4. افتح الرابط الذي يعرضه Vite، غالبًا `http://localhost:5173`.
5. البيانات تحفظ في `localStorage` للمتصفح الحالي. لا تمسح بيانات المتصفح قبل تنزيل نسخة احتياطية.

## بناء نسخة للنشر
```bash
npm run build
npm run preview
```
ينتج مجلد `dist/`. يمكن نشر محتوياته على Vercel أو Netlify أو أي استضافة ملفات ثابتة تدعم تطبيقات Vite. عند استخدام مسار فرعي، راجع إعداد `base` في Vite.

## الميزات الموجودة
- واجهة عربية RTL متجاوبة.
- لوحة تحكم ومؤشرات مبيعات ومديونيات وتنبيهات داخل التطبيق.
- إضافة وتعديل العملاء، أرصدة افتتاحية، البحث والتفاصيل.
- فواتير نقدية وآجلة، ترقيم سنوي تلقائي مثل `2026-001`، استحقاق بعد 30/45/60 يومًا.
- التحصيل النقدي التلقائي للفواتير النقدية، وتحويل التحصيلات اليدوية المرتبطة إلى فاتورة أو رصيد افتتاحي.
- منع التحصيل الأكبر من الرصيد المتبقي، تحصيل جزئي/كامل، تعديل وإلغاء التحصيلات مع سجل مراجعة.
- تقارير شهرية وسنوية، مقارنة السنوات، حساب العمولة والخصم الشهري/السنوي دون ازدواجية الخصم.
- استيراد CSV وExcel مع معاينة وتحديد الصفوف بلا تاريخ والتكرارات المحتملة؛ المستورد تاريخي ولا ينشئ مديونية.
- تصدير الجداول إلى CSV متوافق مع Excel، طباعة وحفظ PDF من نافذة الطباعة في المتصفح.
- نسخة احتياطية JSON واستعادة، وسجل مراجعة.
- SQL أولي لجداول Supabase وسياسات RLS.

## قواعد الحساب الافتراضية
- الرصيد المستحق = الرصيد الافتتاحي المتبقي + أرصدة الفواتير الآجلة.
- التحصيل مربوط إما بفاتورة محددة أو بالرصيد الافتتاحي للعميل، ولا يخصم من الاثنين.
- الفاتورة النقدية تسجل تحصيلًا تلقائيًا كاملًا ولا تزيد المديونية.
- العمولة الشهرية = نسبة العمولة × `max(0, مبيعات الشهر - الخصم الشهري)`.
- العمولة السنوية = نسبة العمولة × `max(0, مبيعات السنة - 12 × الخصم الشهري)`.
- لا تجمع العمولات الشهرية ثم تخصم الخصم السنوي مرة ثانية. القاعدة السنوية مستقلة كما يظهر في التقرير.
- لا تتحول السجلات التاريخية المستوردة إلى مديونيات.

## الاستيراد التاريخي
- الأعمدة المدعومة تلقائيًا بالبحث التقريبي: التاريخ/Date، العميل/Customer، المبلغ/Amount أو الإجمالي/Total، رقم الفاتورة/Invoice Number.
- الأفضل ترتيب الملف بحيث يكون صف العناوين في الصف الأول.
- إذا لم يتعرف التطبيق على عمود بسبب اختلاف اسمه، أعد تسمية عنوان العمود إلى: `التاريخ`، `العميل`، `المبلغ`، `رقم الفاتورة`.
- الصفوف بلا تاريخ لا تُمنح تاريخًا افتراضيًا، ويمكن تصديرها للمراجعة.
- الصفوف المتشابهة تُعلّم كتكرارات محتملة ولا تُحذف تلقائيًا.
- التصدير الحالي CSV؛ يمكن فتحه في Excel. تصدير PDF يتم عبر الطباعة > حفظ كـ PDF.

## إعداد Supabase (تهيئة، وليست مزامنة مكتملة في هذا الإصدار)
1. أنشئ مشروعًا في Supabase.
2. افتح SQL Editor ونفّذ محتوى `supabase/schema.sql`.
3. انسخ `.env.example` إلى `.env.local`.
4. ضع `Project URL` و`anon/publishable key` فقط في الملف.
5. شغّل `npm run dev` من جديد.
6. فعّل مزود تسجيل الدخول من إعدادات Supabase، ثم اختبر تسجيل الدخول وسياسات RLS قبل تخزين بيانات حقيقية.

**مهم:** هذا الإصدار لا يزامن سجلات التطبيق المحلية تلقائيًا مع Supabase ولا يحتوي بعد على واجهة تسجيل دخول؛ ملف SQL وعميل Supabase مجرد نقطة بدء للبناء. لا تعتبر المزامنة أو المصادقة مفعلة قبل تطوير طبقة المستودع واختبارها فعليًا. لا تضع `service_role` key في الواجهة.

## ملاحظات أمان ومحاسبة
- التخزين المحلي مناسب للتجربة على جهاز واحد، وليس قاعدة بيانات إنتاجية مشتركة بين عدة أجهزة.
- لا تستخدم بيانات عملاء حقيقية قبل استكمال المصادقة والربط السحابي والاختبارات الأمنية.
- حذف عميل له فواتير/تحصيلات ممنوع للحفاظ على السجل المالي.
- لا يمكن تعديل فاتورة عليها تحصيل يدوي حتى إلغاء التحصيل أولًا.
- التحصيلات النقدية التلقائية مرتبطة بالفاتورة وتُحذف معها عند حذف الفاتورة.
- يوصى باختبار النظام على نسخة من البيانات ومراجعة سياسة العمولات مع المحاسب قبل الاعتماد الرسمي.

## الاختبارات التي نُفذت ضمن فحص المشروع
- مراجعة ملفات المشروع وملف SQL ووجود آليات التحقق من المدخلات.
- لم يُنفذ اختبار متصفح آلي شامل أو اتصال حقيقي بمشروع Supabase في بيئة الإنشاء هذه.
- لم يتم اختبار المزامنة متعددة الأجهزة، لأن طبقة المزامنة والمصادقة لم تُستكمل بعد.
